# sota-deck

자료를 읽고 SOTA 랩 템플릿 위에 python-pptx 로 덱을 짠다. 글, 도형, 표, 코드는 모두 PowerPoint 에서 바로 고칠 수 있는
네이티브 개체다. 그림 파일과 아이콘은 넣지 않는다.

## 0. 먼저 읽을 것

```bash
python3 ${CLAUDE_SKILL_DIR}/scripts/lessons.py      # 사용자 피드백으로 쌓인 규칙 (diagram-deck/LESSONS.md 중 적용 항목)
```

- 그 규칙과 아래 §4 문체 규칙을 지킨다. 둘이 어긋나면 LESSONS 가 최신이다.
- 슬라이드 유형은 `scripts/example_deck.py` 의 함수 하나가 한 유형이다. 맞는 함수를 복사해 내용만 바꾼다.

## 1. 준비

```bash
python3 -c "import pptx, PIL, lxml" || pip install python-pptx    # 샌드박스에서는 --break-system-packages
python3 ${CLAUDE_SKILL_DIR}/scripts/setup_fonts.py                # 렌더 검수용 글꼴. PowerPoint 에는 필요 없다
```

템플릿은 이 순서로 찾는다 (`sota.find_template`).

| 순서 | 위치 |
|---|---|
| 1 | `Deck("경로")` 로 넘긴 파일 |
| 2 | 환경변수 `SOTA_TEMPLATE` |
| 3 | `${CLAUDE_SKILL_DIR}/assets/SOTA_ppt_template_v5.pptx` (`.gitignore` 로 저장소에 안 올라간다) |
| 4 | 현재 폴더, 그 바로 아래 폴더, `/mnt/user-data/uploads/` 의 `SOTA_ppt_template*.pptx` |

못 찾으면 사용자에게 템플릿 파일을 받는다. 다른 템플릿이면 레이아웃 이름(`제목 슬라이드`, `목차`, `제목만`, `마무리`)부터
확인한다. 없으면 `Deck` 이 있는 이름을 알려 주며 멈춘다.

## 2. 자료를 읽고 내용을 고른다

1. 첨부 자료는 끝까지 읽는다. docx 는 `pandoc -t gfm` 으로 바꿔 읽는다. 사용자 컴퓨터가 연결돼 있으면 연결 폴더의
   원본 코드도 찾아본다.
2. 1차 근거로 확인한다. 소스 코드가 있으면 코드, 남의 방법은 논문 본문이다 (L-20, L-21). 요약 문서와 다르면 1차 근거를
   슬라이드에 쓰고, 다른 점을 메모와 보고에 적는다.
   (2026-11-02 실측: 강의 요약본과 실제 강의 코드가 버전, 라우팅 기본값, 승인 기준 세 곳에서 달랐다.)
3. 슬라이드 계획표를 먼저 적는다.

   | 번호 | 제목 (명사구) | 그림, 표, 코드 | 메모 요점 |
   |---|---|---|---|

4. 덱 순서는 표지, 목차, 내용, 사용자가 원하면 "추가로 공부하면 좋은 개념", 마무리다. 요약이나 정리 슬라이드로 끝내지
   않는다 (L-28). 덱 전체 비교표가 필요하면 목차 다음에 둔다.
5. 개념은 정의를 먼저, 코드와 사용은 그 뒤에 둔다 (L-39, L-51). 처음 나오는 용어는 그 슬라이드에서 뜻을 적는다.
6. 사용자가 자기 정리 방식을 보여 주면 그 형식을 따른다. 예: 강의 덱은 제목 "Chapter N. 영문 제목" 아래에
   회색 부제 "(공식 한글 부제)".

## 3. 덱을 짠다

```python
import sys; sys.path.insert(0, "${CLAUDE_SKILL_DIR}/scripts")
from sota import *

d = Deck()                                                # 템플릿 자동 탐색
d.title_slide(["첫 줄", "둘째 줄"], "부제", "발표자", notes=["..."])
d.contents([("01", "장 이름", "3 ~ 5"), ("02", "장 이름", None)])
s = d.slide("시스템 구성도", sub="(공식 부제가 있을 때만)", notes=["훑어볼 때 볼 것", "..."])
d.head(s, X0, 2.0, CW, "무엇을 그렸나")                   # "그림 1: 무엇을 그렸나"
node(s, X0, 2.5, 2.0, 0.8, "이름", "보조 줄", dark=False)
harrow(s, x1, x2, y, label="라벨")                        # 가로 화살표와 라벨
bullets(s, X0, 4.8, CW, 1.2, ["설명 한 줄", "설명 한 줄"])
y = d.code_block(s, X0, 2.0, 6.8, src, "java", what="파일, 무엇")    # "코드 N: 파일, 무엇" 과 코드 상자
numbered(s, 7.95, 2.42, X1 - 7.95, 2.0, ["1번 줄 설명", "2번 줄 설명"])
d.head(s, X0, 4.5, CW, "무엇을 비교했나", kind="표")
table(s, X0, 4.92, CW, [2, 4.75, 4.75], [["머리", "열", "열"], ["값", "값", "값"]], hl={(1, 2)})
d.closing("발표자")
d.save("/abs/out/deck.pptx")                              # "저장 ... (슬라이드 N장)" 이 찍혀야 빌드 성공 (L-43)
```

| 슬라이드 유형 | example_deck.py 함수 | 쓰는 때 |
|---|---|---|
| 구성도 | `system_map` | 부품과 연결, 포함 관계 |
| 처리 흐름과 표 | `pipeline` | 순서 있는 단계와 단계별 입출력 |
| 코드 분석 | `code_walk` | 실제 소스, 줄 번호 설명, 그 코드가 만드는 흐름 |
| 비교표와 작은 그림 | `compare` | 방식 비교, 틀린 칸 표시 |
| 비교 카드 | `patterns` | 3~5개 방식을 같은 틀로 나란히 |
| 행 흐름 | `rows` | 준비, 설치처럼 줄마다 단계가 다른 흐름 |
| 카드 격자 | `study` | 추가로 공부할 개념 |

화면 틀: 본문 `X0..X1` = 0.92..12.42in, `Y0..Y1` = 2.0..6.6in, 부제 줄 1.40..1.76in, 꼬리말은 6.95in 부터.

## 4. 문체 규칙

사용자가 직접 지적한 것이다. `sota.py` 는 금지 문자와 11pt 미만 글자를 쓰는 순간 예외로 막는다.

| 하지 않는다 | 대신 |
|---|---|
| 가운뎃점, 줄표, 문장 속 화살표 문자, 체크 표시, 원문자, 참고표, 말줄임표, 이모지 | 쉼표, 빗금, `1.` 번호, 코드 주석 `// 1`, 문장 |
| 아이콘, 그림 파일, 노란 강조, 알약 라벨, 제목 위 꼬리표 | 없앤다. 그림은 도형으로 그린다 |
| "왜?", "참고" 같은 덧붙임 줄, 쓸데없는 부연 | 지운다. 필요하면 발표자 메모로 |
| 설명을 상자 여러 개에 나눠 담기 | 글상자 하나에 글머리 기호 `bullets`, 코드 설명은 `numbered` (L-29) |
| 표 아래 "핵심" 요약 상자 | 없음. 조건은 부제로, 열 설명은 메모로 (L-42) |
| 의문형 제목 | 명사구 (L-46) |
| 상자 안에 문장 여러 줄 | 상자에는 라벨만. 문장은 표나 글머리로 (L-24, L-41) |
| 색 글자 | 잉크, 회색만. 강조는 굵기 `F_MED`. 틀린 것은 연한 빨강 채움 `hl` (L-32) |
| 이름 없는 그림 | 위에 `그림 N: 무엇` 이름표 `d.head` (L-38) |

글자 크기는 역할마다 하나다 (L-30, L-47). 안 들어가면 크기를 줄이지 말고 글을 줄이거나 슬라이드를 나눈다.

| 역할 | 크기 | 상수 |
|---|---|---|
| 제목 | 템플릿 32pt | |
| 부제, 이름표 | 14pt | `SUB_PT`, `HEAD_PT` |
| 글머리, 번호 설명, 표 | 12pt | `BODY_PT`, `TABLE_PT` |
| 도형 이름 | 12pt | `NODE_PT` |
| 도형 보조 줄, 화살표 라벨, 코드 | 11pt | `NODE_SUB_PT`, `CODE_PT` |

색은 무채, 남색 계열(템플릿 강조색), 틀린 것 표시용 연한 빨강 채움뿐이다. 코드 상자 안의 문법 색만 예외다.
표지, 목차, 마무리의 남색 글자는 템플릿 모양이라 그대로 둔다.

## 5. 발표자 메모

- 내용 슬라이드마다 3~6줄, 줄마다 `- ` 로 시작한다. `notes=[...]` 에 넘기면 붙여 준다.
- 훑어볼 때 도움이 되는 것만 적는다: 숫자, 이름, 함정, 근거 위치(파일, 강의 번호), 슬라이드에 못 넣은 이유.
- 쉬운 말로 짧게. 슬라이드 글을 되풀이하지 않는다.

## 6. 검수 루프

통과할 때까지 돈다. 통과 전에는 내지 않는다. 경로는 절대 경로로 쓴다 (L-50).

```bash
python3 /abs/build.py                                               # "저장 ... (슬라이드 N장)" 부터 확인 (L-43)
python3 ${CLAUDE_SKILL_DIR}/scripts/check_deck.py /abs/out/deck.pptx
python3 ${CLAUDE_SKILL_DIR}/scripts/render.py /abs/out/deck.pptx /abs/out/render
```

`check_deck.py` 가 보는 것: 금지 문자(슬라이드와 메모), 11pt 미만 글자, 템플릿 밖 글꼴, 색 글자, 메모 형식,
제목 길이, 나중 도형에 가려진 글, 역할별 크기 통일, 이름표 번호, 그림 개체, 소수 좌표, 날 개행,
그리고 diagram-deck 의 `check_ooxml.py`, `check_layout.py` (내용 슬라이드만 남긴 사본으로).

렌더한 `pair-*.jpg` 를 Read 로 전부 본다. 검사기가 못 잡는 것:

- 낱말 하나만 다음 줄로 넘어간 줄바꿈: 글을 줄이거나 `\n` 으로 직접 끊는다
- 라벨과 화살표, 상자 테두리의 겹침 (L-27)
- 빈 띠, 한쪽에 몰린 배치 (L-25)
- 코드 줄이 상자 폭을 넘어 접힌 것

LibreOffice 렌더는 PowerPoint 와 다르다. 4 Regular, 5 Medium 은 3 Light 글리프로 대신 그리므로 실제 굵은 글자가
조금 더 넓다. 코드는 Consolas 대신 DejaVu Sans Mono 로 그려 실제보다 약 10% 넓다. 꽉 찬 글자는 여유를 둔다.

## 7. 낼 때

- `.pptx` 와 생성 스크립트를 함께 남긴다. 사용자의 원본 덱은 덮어쓰지 않고 새 이름으로 저장한다.
- 사용자 컴퓨터가 연결돼 있으면 사용자가 말한 폴더에도 저장한다.
- 보고: 무엇을 검사해 몇 건이었는지, 자료와 1차 근거가 달랐던 점.

## 8. 고쳐 달라고 하면

`diagram-deck-upgrade` 를 따른다 (훅이 부른다). 교훈은 `diagram-deck/LESSONS.md` 한 곳에 남긴다. 훅이 그 파일만 지키기
때문이다. 템플릿 덱에만 해당하는 교훈은 제목 앞에 `[sota-deck]` 을 붙인다. `lessons.py` 가 새 항목을 자동으로 보여 준다.
고친 덱의 검증은 이 스킬의 `check_deck.py` 로 한다.

## 주의

- 템플릿 파일을 저장소에 커밋하지 않는다. 저장소가 공개이고 학교 로고가 들어 있다. `assets/*.pptx` 는 `.gitignore` 에 있다.
- python-pptx 는 레이아웃의 쪽 번호를 슬라이드로 복사하지 않는다. `Deck.slide()` 가 복사한다.
- 자리표시자의 높이만 바꾸면 위치가 (0,0) 으로 새로 잡혀 글이 사라진다. 네 값을 다 넣는다 (`title_slide` 참고).
- 화살표 라벨은 틈이 라벨보다 넓을 때만 단다. 좁으면 뒤에 그린 상자가 라벨을 가린다 (검사기가 잡는다).
- 원문을 그대로 실으면 금지 문자가 섞여 온다 (코드 주석, 설명 문자열). 발췌를 줄여 빼거나 같은 뜻의 글로 바꾼다.
