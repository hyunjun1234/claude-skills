# md 작성 규칙

## 원칙

**서사 없이 명령·코드 중심으로.** 문서는 읽고 따라 하는 것이지 읽고 감상하는 것이 아니다.
독자가 그대로 복붙해 실행할 수 있는 상태가 완성이다.

## 문서의 모양

1. `# 제목` — 대상이 무엇인지
2. 스코프 한두 줄 — 다루는 범위·전제. 서론·배경·의의 문단이 아니다
3. `##` 섹션들 — 아래 재료로만 조립:
   - **명령 블록**: 경로·환경변수 포함, 복붙 즉시 실행되게. 설명은 `#` 주석 한 줄
   - **표**: 선택지·결정에는 근거 열을 붙인다 — `| 결정 | 근거 |`
   - **ASCII 도식**: 구조·흐름·배치는 문단 설명 대신 코드펜스 안 그림으로
   - **체크리스트·사다리**: 순서 있는 작업은 번호나 `✓` 진행표로
4. 함정·제약은 `주의` 섹션이나 ★ 로 모은다 — 본문에 흩뿌리지 않는다

## 사실 규칙

- 단정에는 근거를 붙인다: 실측 날짜, `파일:줄번호`, 실행 출력.
  예: `(2026-08-06 실측: 10/10)`, `constraints.rs:25 의 CLUSTER_SIZES = [1, 2]`
- 하드웨어·버전·API 에 대한 주장은 소스나 실행으로 확인한 것만 적는다.
  미확인이면 "~로 보인다" 로 표시하거나 빼라
- 문서에 적는 명령은 실제로 돌려 본 것이어야 한다. 핵심 출력을 요약해 같이 싣는다

## 갱신 규칙

- 수정할 땐 낡은 주장을 **삭제**한다. 새 문장을 덧붙이고 옛 문장을 남기면
  문서 앞뒤가 모순된다 (8줄에서 "안 된다", 60줄에서 "된다" 꼴)
- 날짜가 박힌 주장을 고치면 날짜도 갱신한다
- 같은 내용이 두 문서에 있으면 한쪽을 지우고 포인터로 바꾼다 — `자세한 것은 X 참고`

## 자주 하는 실수

| 실수 | 고침 |
|---|---|
| 서론·배경·의의 문단 | 삭제. 스코프 한두 줄이면 충분 |
| "간단히 실행할 수 있습니다" 류 홍보투 | 명령 블록으로 대체 |
| 근거 없는 하드웨어·버전 단정 | 소스·실측 확인 후 근거 병기 |
| 갱신하며 옛 문장을 남김 | 낡은 주장 삭제. 문서 전체를 다시 읽어 모순 확인 |
| 안 돌려본 명령 수록 | 돌려 보고 출력과 함께 |
