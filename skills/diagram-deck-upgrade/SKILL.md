# diagram-deck-upgrade — 피드백을 스킬에 영구히 반영한다

사용자가 그림을 고쳐 달라고 했다. **고치는 것은 절반이다.** 나머지 절반은 같은 지적을
다시 받지 않도록 규칙으로 만들어 남기는 것이다.

## 1. 먼저 고친다

1. `diagram-deck` 스킬의 `LESSONS.md` 를 읽는다. **이미 적힌 규칙을 어겨서 생긴 문제인지 먼저 본다.**
   - 이미 적혀 있는데 어겼다면 → 규칙이 안 지켜진 이유를 본다. 규칙이 모호하면 §3 에서 더 명확히 고친다.
   - 새 문제라면 → §3 에서 새 규칙을 추가한다.
2. 요청대로 그림을 고치고 `diagram-deck` §7 검증 루프를 돌린다.
3. 고친 결과를 사용자에게 보인다.

## 2. 교훈을 뽑는다 — 한 번만 쓰고 버릴 것인가, 규칙인가

기록할 가치가 있는 것:

- **재발할 수 있는 것.** "이 그림의 화살표를 왼쪽으로" 는 일회성이다. 기록하지 마라.
  "화살표는 항상 데이터가 흐르는 방향으로 그린다" 는 규칙이다. 기록한다.
- **취향이 드러난 것.** 색, 밀도, 글자 크기, 강조 방식, 설명량.
- **기술적으로 물린 것.** 렌더 깨짐, 폰트, 여백, 좌표, 파일 손상.
- **판단 기준.** "이건 그림보다 표가 낫다" 같은 것.

기록하지 말 것: 그 문서에만 해당하는 내용, 사실 정정(그건 문서를 고치면 된다).

## 3. LESSONS.md 에 추가한다

`<skill>/LESSONS.md` 의 알맞은 절에 항목을 넣는다. 형식:

```markdown
### L-<번호> <한 줄 제목>
- **지적**: 사용자가 뭐라고 했는지 (그대로 인용하면 좋다)
- **원인**: 왜 그렇게 됐는지
- **규칙**: 앞으로 어떻게 할 것인지 — **행동으로 쓴다.** "주의한다" 같은 말은 규칙이 아니다.
- **검사**: 자동으로 잡을 수 있으면 어떻게 잡는지. 못 잡으면 "눈으로 확인" 이라고 적는다.
```

번호는 이어서 붙인다. 기존 규칙을 더 정확히 고치는 것이면 새로 만들지 말고 **그 항목을 고친다.**

## 4. 자동 검사로 만들 수 있으면 만든다

규칙이 기계로 잡히는 것이면 `scripts/check_layout.py` 나 `scripts/check_ooxml.py` 에 검사를 추가한다.
예: "선택 박스가 크다" → 여백 트림 비율 검사, "글자가 넘친다" → 넘침 추정 검사.

검사를 추가했으면 **일부러 어긴 입력으로 걸리는지 확인한다.** 안 걸리면 검사가 아니다.

## 5. 커밋하고 푸시한다 — 이걸 빠뜨리면 다른 환경에 반영되지 않는다

```bash
cd ~/claude-skills
git add -A
git commit -m "lessons: <한 줄 요약>"
git push
```

푸시하지 않으면 이 기계 밖에서는 옛 스킬이 그대로 쓰인다.

## 6. 사용자에게 보고할 것

- 무엇을 고쳤는지
- **어떤 규칙을 스킬에 새로 넣었는지 (L-번호와 한 줄)**
- 자동 검사를 추가했으면 그것도
- 커밋 해시

## 7. 하지 말 것

- 교훈 없이 고치고 끝내기. 그러면 이 스킬을 쓴 의미가 없다.
- 일회성 요청을 규칙으로 승격하기. LESSONS.md 가 잡음으로 차면 아무도 안 읽는다.
- "앞으로 주의하겠다" 류의 규칙. 행동으로 쓸 수 없으면 규칙이 아니다.
